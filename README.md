# specgen — генератор интеграций с платёжными провайдерами

Инструмент на Ruby, который принимает OpenAPI-спецификацию платёжного
провайдера и собирает из неё готовую интеграцию для Space Payments: сервис по
контракту `Provider::BaseService`, документацию, фикстуры и отчёт о том, что в
спецификации неоднозначно.

Это компилятор, а не интеграция с одним провайдером. Спецификация превращается
в нейтральную модель провайдера, из модели по шаблонам собираются артефакты.
Всё, что выводится формально, выводится детерминированно по открытым
стандартам (ISO 4217, OpenAPI Overlay 1.0.0, JSON Schema, Standard Webhooks,
IETF Idempotency-Key). Всё, что формально не выводится, попадает в отчёт, а не
угадывается молча.

Хакатон Hack.Genesis 2026, кейс 1 (Space Payments).

> **Состояние: скелет (v0.1.0).** CLI разбирает и проверяет аргументы, стадии
> конвейера подключаются по одной. Готовность стадий — в таблице ниже.

## Быстрый старт

Нужны Ruby 3.2 или новее и Bundler.

```sh
git clone <repo-url> hackgenesis
cd hackgenesis
bundle install

# спецификация → четыре артефакта в output/
./integrate --spec spec/fixtures/specs/novapay.yaml --provider novapay --lang ruby

ls output/
#   novapay_service.rb   сервис по контракту Provider::BaseService (379 строк)
#   INTEGRATION.md       документация интеграции: авторизация, ENV, маппинги (218)
#   fixtures.json        примеры запросов, ответов и webhook-уведомлений (461)
#   report.md            неоднозначности, покрытие спеки, что доделать руками (228)
```

Одна команда пишет все четыре файла и заканчивает строкой о предупреждениях.
Отчёт `report.md` — семь разделов: сводка, покрытие спецификации одной цифрой,
неоднозначности с готовыми фрагментами OpenAPI Overlay, операции вне контракта,
противоречия в самой спецификации, справки и нумерованный список того, что
доделать руками.

> **Состояние (сентябрь 2026):** загрузка, анализ и генерация работают,
> впереди валидаторы и мок-провайдер. Текущий статус каждой стадии и способ её
> проверить — в `docs/STATUS.md`.

Посмотреть, что генератор понял в спецификации, **не генерируя ничего**:

```sh
./integrate analyze --spec spec/fixtures/specs/novapay.yaml
./integrate analyze --spec spec/fixtures/specs/novapay.yaml --provider novapay --explain
```

Печатает промежуточное представление: провайдера и серверы, авторизацию,
каждую операцию с ролью и уверенностью, каждую схему с полями, типами,
обязательностью и ограничениями, и предупреждения. Рядом с каждым выведенным
значением стоит его источник («задано явно», «по справочнику», «эвристика») и
уверенность. С `--explain` под каждым значением печатается обоснование — та же
фраза, из которой потом собирается строка `report.md`, — а под каждым
исправимым предупреждением — готовый фрагмент OpenAPI Overlay.

Язык всего, что печатает инструмент, — русский по умолчанию. Английский:

```sh
./integrate analyze --spec spec/fixtures/specs/novapay.yaml --locale en
SPECGEN_LOCALE=en ./integrate --help
```

Тексты лежат в `locales/<код>/`, по файлу на стадию конвейера; новый язык —
новый каталог, без правки кода. Справка `--help` читается при запуске, поэтому
следует переменной окружения, а не флагу.

В PowerShell вместо `./integrate` пишите `ruby integrate`. На Windows нужен
RubyInstaller **с DevKit (MSYS2)**: RuboCop тянет нативные расширения
(`prism`, `bigdecimal`), и без компилятора `bundle install` не пройдёт.

Прогон на всех тестовых спецификациях сразу, со сводной таблицей по
провайдерам:

```sh
./integrate --all
```

Справка:

```sh
./integrate --help
./integrate help generate
```

## Как это работает

```
 provider_api.yaml             overlay.yaml (необязательно)
        │                             │
        ▼                             ▼
 ┌─────────────┐    ┌────────────────┐
 │ SpecLoader  │───▶│ OverlayApplier │  читает YAML/JSON, разрешает $ref,
 └─────────────┘    └────────────────┘  применяет OpenAPI Overlay 1.0.0
                            │
                            ▼
                    ┌────────────────┐
                    │   Analyzers    │  независимые анализаторы: операции,
                    └────────────────┘  авторизация, схемы, статусы, ошибки,
                            │           вебхуки, единицы суммы, идемпотентность
                            ▼
                    ┌────────────────┐
                    │       IR       │  ProviderProfile: нейтральная модель
                    └────────────────┘  провайдера, каждое значение помечено
                            │           источником и уверенностью
                            ▼
                    ┌────────────────┐
                    │   Generators   │  ERB-шаблоны → service.rb,
                    └────────────────┘  INTEGRATION.md, fixtures.json
                            │
                            ▼
                    ┌────────────────┐
                    │   Validators   │  ruby -c, RuboCop, сверка запросов со
                    └────────────────┘  спекой, покрытие спецификации
                            │
                            ▼
                    ┌────────────────┐
                    │    Reporter    │  report.md: предупреждения, покрытие,
                    └────────────────┘  готовые фрагменты overlay
```

Каждая стадия — отдельный каталог в `lib/specgen/`:

| Стадия | Каталог | Что делает | Готовность |
|---|---|---|---|
| SpecLoader | `lib/specgen/spec_loader/` | YAML/JSON, версия OAS, `$ref`, циклы | скелет |
| OverlayApplier | `lib/specgen/overlay/` | OpenAPI Overlay 1.0.0: `update` / `remove` по JSONPath | скелет |
| Analyzers | `lib/specgen/analyzers/` | каждый анализатор заполняет свою часть IR | скелет |
| Matchers | `lib/specgen/matchers/` | имя поля → роль: словарь, тип, ограничения, структура | скелет |
| IR | `lib/specgen/ir/` | `ProviderProfile` и `Derived` (значение, источник, уверенность) | скелет |
| Generators | `lib/specgen/generators/` | ERB-шаблоны из `templates/` | скелет |
| Validators | `lib/specgen/validators/` | синтаксис, линтер, сверка со спекой | скелет |
| Reporter | `lib/specgen/reporter/` | `report.md` | скелет |

### Три уровня доверия

Для каждого элемента спецификации идём по цепочке и останавливаемся на
первом успехе:

1. **Формальная структура спеки** (`required`, `enum`, `pattern`, `minimum`,
   `format`, `$ref`, `securitySchemes`) — используем молча.
2. **Справочники и структурные эвристики** (ISO 4217, словари синонимов,
   роли эндпоинтов по методу, пути и тегу) — используем, помечаем источник и
   уверенность.
3. **Не вывелось или низкая уверенность** — предупреждение в `report.md`,
   `TODO` в сгенерированном коде и готовый слот в overlay-файле.

Молчаливая ошибка в платёжной интеграции дороже одного ручного шага: неверно
выведенный множитель суммы означает перевод в сто раз больше, а код при этом
выглядит корректным.

### Роли вместо имён полей

Имён полей бесконечно много (`amount`, `sum`, `total`, `value`), ролей в
платёжной области около пятнадцати. Ядро работает с ролями, сопоставление
«имя → роль» делает слой матчеров по принципу composite matcher (COMA).
Новый провайдер — новые строки в справочниках `rules/`, а не новый код.

Инвариант: в `lib/` нет ни одной провайдер-специфичной строки. Проверяется
командой `grep -rinE 'novapay|bank_code|sbp' lib/`, результат пустой.

## Структура репозитория

```
integrate                 запуск из корня (./integrate ...)
bin/integrate             исполняемый файл CLI
lib/specgen.rb            точка входа библиотеки
lib/specgen/cli.rb        Thor-команды generate и diff
lib/specgen/errors.rb     иерархия SpecGen::Error
lib/specgen/<стадия>/     по каталогу на стадию конвейера (см. таблицу выше)
templates/                ERB-шаблоны артефактов
rules/                    справочники: роли, статусы, ISO 4217, подписи, контракт
spec/unit/                RSpec ядра
spec/fixtures/specs/      тестовые спецификации (novapay.yaml и альтернативные)
spec/fixtures/golden/     эталонный вывод для golden-тестов
examples/                 сквозные примеры (smoke-прогон с мок-провайдером)
docs/                     концепция, разбалловка, допущения, вопросы экспертам
output/                   результат генерации, в репозиторий не попадает
```

## Команды и флаги

| Команда / флаг | Назначение |
|---|---|
| `generate` | генерация артефактов, команда по умолчанию |
| `--spec FILE` | путь к OpenAPI-спецификации (YAML или JSON) |
| `--provider NAME` | имя провайдера; по умолчанию выводится из `info.title` |
| `--lang ruby` | целевой язык, поддерживается только `ruby` |
| `--overlay FILE` | OpenAPI Overlay 1.0.0 с ручными переопределениями |
| `--output DIR` | каталог результата, по умолчанию `output/` |
| `--with-mock` | дополнительно сгенерировать мок-сервер провайдера |
| `--fix` | записать скелет overlay со слотом `TODO` на каждую неоднозначность |
| `--strict` | завершиться с кодом 1, если в отчёте есть предупреждения |
| `--all` | прогнать все спеки из `spec/fixtures/specs/` и напечатать сводку |
| `diff --old FILE --new FILE` | изменения между версиями спеки, влияющие на интеграцию |
| `version` | версия генератора |

Коды возврата: `0` успех, `1` ошибка генерации или предупреждения при
`--strict`, `2` неверное использование.

## Разработка

```sh
bundle exec rspec       # тесты
bundle exec rubocop     # линтер; тот же конфиг применяется к сгенерированному коду
./integrate --help      # smoke-проверка CLI
```

CI (GitHub Actions) прогоняет то же самое на Ruby 3.2 и 3.4.

Definition of done для любой задачи описан в `CLAUDE.md`: зелёные `rspec` и
`rubocop`, сквозной прогон на `novapay.yaml`, `ruby -c` на сгенерированном
коде, байт-в-байт повторяемость вывода, прогон на альтернативных спеках,
отсутствие провайдер-специфичных строк в `lib/`.

## Правила хакатона

| Требование | Как соблюдаем |
|---|---|
| Без нейросетей в прототипе | только справочники, регулярные выражения, строковые метрики, эвристики по структуре; детерминированность доказывается golden-тестами |
| Ruby больше 50% кода | ядро целиком на Ruby, веб-интерфейс, если появится, только Rack и ERB без npm |
| Только открытый код | все зависимости с открытыми лицензиями, список в [DEPENDENCIES.md](DEPENDENCIES.md) |
| Без секретов | сгенерированный код читает ключи из `provider.credentials` или `ENV.fetch`, в фикстурах только заглушки |
