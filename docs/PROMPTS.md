# Промпты для Claude Code

Готовые промпты по порядку. У каждого есть **критерии приёмки** — ссылки на
идентификаторы из `docs/RUBRIC.md`. Не переходи к следующему промпту, пока
критерии текущего не выполняются на живом прогоне.

Не склеивай промпты. Агенты работают лучше, когда задача одна.

Перед началом: `CLAUDE.md` в корне, `.claude/agents/` на месте. Проверить —
команда `/agents`.

## Промпт 3. Справочники

```
Используй агента rules-curator. Создай справочники в rules/:

- roles.yml — пятнадцать ролей с синонимами, включая транслит (bik и bic)

- currencies.yml — полная таблица ISO 4217, экспоненты минорных единиц

- idempotency.yml — алиасы заголовков
- auth.yml — схемы авторизации → генерируемый код

  внутренних статусов, семантика request_method. Если эксперты уточнят
  контракт, мы правим этот YAML, а не шаблоны.

В каждом файле комментарий сверху: что это, откуда данные, как расширять.

Затем загрузчик справочников с валидацией: конфликт синонимов между ролями
падает с внятной ошибкой при старте, а не берёт молча первое совпадение.
```

## Промпт 6. Матчеры полей

```
Используй агента spec-analyst. Composite matcher по подходу COMA:

- NameMatcher: словарь → токенизация → расстояние Левенштейна
- TypeMatcher: type и format
- ConstraintMatcher: pattern, enum, minimum, maxLength
- StructureMatcher: путь в схеме, имя родителя

Агрегация с весами, порог 0.6. Ниже порога роль не присваивается, пишется
warning с перечислением того, что насчитал каждый матчер — это пойдёт в
evidence отчёта.

Тесты обязательно включают:
- pattern ^7\d{10}$ определяет телефон при имени поля contact
- поле xref_tag_9 не получает роль и даёт warning
- amount и sum сопоставляются через словарь, а не метрикой строк
- обязательное поле без роли и необязательное без роли обрабатываются
  по-разному
```

**Приёмка:** E3.1 (8 баллов), T3.2.

## Приёмы в работе

**Fable на xhigh для анализаторов и шаблонов, Sonnet для справочников.** В
Claude Code Fable по умолчанию High. Максимальный уровень не ставьте: расход
токенов растёт быстрее пользы.

**Задача — один этап.** «Реализуй все анализаторы» хуже, чем два промпта по
четыре. Длинный контекст размывает требования из `CLAUDE.md`.

**Требуй прогонов, не отчётов.** Добавляй в конец: «прогони и покажи вывод».
Иначе «готово» может означать «написал, не проверял».

**Коммить по завершённому этапу.** История коммитов — предмет внимания при
разработке с ИИ.

**Промпт 14 перед каждым чекпоинтом**, особенно перед третьим.
