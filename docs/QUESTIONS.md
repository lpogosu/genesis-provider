# Вопросы к экспертам

Открытые вопросы, ответы на которые меняют реализацию. Не выдумываем ответы:
пока вопрос открыт, в коде стоит допущение из `ASSUMPTIONS.md` с пометкой,
что оно ждёт подтверждения.

Правила ведения:

- вопрос формулируется так, чтобы на него можно было ответить одной фразой
- ответ записывается дословно, с датой и чекпоинтом, на котором получен
- после ответа вопрос закрывается, а следствие переносится в
  `ASSUMPTIONS.md` или в справочники `rules/`

| # | Вопрос | Зачем нам ответ | Ответ (дословно) | Дата | Статус |
|---|---|---|---|---|---|
| 1 | `accepted` — это «запрос принят» или «средства зачислены»? | Сейчас синоним `in_progress` в `rules/statuses.yml`; если второе — статус переезжает в `ambiguous`, и мы предупреждаем вместо маппинга | | | открыт |
| 2 | Какая арность у `approve_operation` и `reject_operation` и что такое `client`? | В `rules/contract.yml` они помечены `source: допущение`; шаблон сервиса вызывает их вслепую | | | открыт |
| 3 | `cancelled` действительно схлопывается в `rejected`, или появится четвёртый внутренний статус? | Канон кейса говорит `rejected`, но отмена логически отдельна; от ответа зависит `IR::Roles::INTERNAL_STATUS` | | | открыт |
| 4 | Подписывает ли кто-то из провайдеров **запросы** (не вебхуки) по HMAC? | В `securitySchemes` это не выражается: сейчас поддержано только через overlay и профиль `hmac_request` в `rules/auth.yml` | | | открыт |
| 5 | `amount_limit_exceeded` — лимит на одну выплату или суточный лимит провайдера? | В `rules/errors.yml` код идёт в `escalate` (человек решает), потому что по имени не различить; если это лимит одной операции — правильнее `reject`, и шаблон `funds` надо разделить | | | открыт |
| 6 | Что делать с 402 Payment Required: ждать пополнения баланса или отклонять операции клиентов? | Сейчас `escalate`: платформа сама баланс провайдера не пополнит, а `reject` потеряет корректные операции. От ответа зависит действие в `rules/errors.yml` и текст `INTEGRATION.md` | | | открыт |
| 7 | В вебхуке одновременно `event` (`payout.failed`) и `status` (`failed`) — что первично для `process_callback`, если они разойдутся? | Сейчас статус события выводится из имени события (снятие префикса) и подтверждается полем `status` только в примерах; при расхождении генератор должен выбрать одно и предупредить | | | открыт |
