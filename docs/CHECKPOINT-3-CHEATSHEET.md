# Шпаргалка на чекпоинт 3

Одна страница для того, кто ведёт показ. Ruby знать не нужно: всё через
Докер, команды копируются целиком. Подробности и запасные ответы — в
`docs/CHECKPOINT-3.md`, текст речи — в `docs/CHECKPOINT-3-PITCH.md`.

---

## За полчаса до созвона

Открыть терминал в папке проекта (`E:\hackgenesis`) и выполнить одну
команду. Она соберёт образ и поднимет веб — дальше он работает сам.

```sh
docker compose up -d --build
```

Проверить, что живо: открыть в браузере <http://localhost:9292> — должен
появиться интерфейс со списком спецификаций.

**Открыть заранее и не закрывать:**

1. терминал в папке проекта, шрифт покрупнее, экран очищен (`clear`);
2. редактор с файлом `output/novapay_service.rb`;
3. редактор с файлом `output/broken/report.md`;
4. браузер на <http://localhost:9292>;
5. редактор с файлом `rules/statuses.yml`, промотанный на строку 271
   (там начинается список `synonyms:`).

## Экран 1. Одна команда — четыре файла

**Вставить в терминал:**

```sh
docker compose run --rm api ./integrate --spec provider_api.yaml --provider novapay --lang ruby
```

**Что появится.** Сначала строки разбора (провайдер, эндпоинты, авторизация,
вебхук), потом четыре строки — по одной на файл, с числом строк. В конце
«Предупреждения: 18».

**Что сказать.** «Это команда из описания кейса, дословно. Кейс просил
четыре вещи — сервис, документацию, фикстуры и интерфейс запуска. Вот они, за
одну команду, ручных шагов между ними нет. И обратите внимание: инструмент
сначала говорит, что он понял, и только потом — что записал».

Файлы появляются в папке `output/` прямо на диске — их и открываем дальше.

## Экран 2. Сгенерированный сервис (самый важный, 25 баллов)

**Ничего не вводить.** Переключиться в редактор с `output/novapay_service.rb`
и промотать на **строку 289**, метод `recipient_requisites`.

**Что показать пальцем — три места подряд:**

1. `when 'sbp'` — ветка по способу выплаты;
2. комментарий `# обязательно при type = sbp (намёк в описании 0.50)`;
3. в ветке `when 'card'` — строка `phone: nil` с TODO над ней.

**Что сказать.**

> «В спецификации написано прозой: если тип получателя СБП — обязателен
> банковский код. Формально это нигде не выражено. Инструмент это правило
> вытянул, оценил свою уверенность в ноль целых пять и превратил в настоящую
> ветку кода».

> «А вот здесь он отказался угадывать. Роль поля опознал — это телефон. Но
> где телефон лежит у платформы в карточной ветке, он не знает. Поставил
> `nil`, написал почему и куда дописать. Догадка о спецификации у нас
> обязательна, догадка о вашей платформе запрещена».

Если есть время — промотать вверх, на строку 61: таблицы `STATUS_MAP` и
`ERROR_MAP`. «Статусы провайдера сопоставлены с внутренними, карта ошибок
собрана объединением того, что в enum, и того, что только в примерах».

## Экран 3. Документация и фикстуры

**Ничего не вводить.** Открыть `output/INTEGRATION.md`, промотать **по
заголовкам**, не построчно. Потом открыть `output/fixtures.json`.

**Что сказать.** «Девять разделов: авторизация, переменные окружения,
таблица методов, статусы, ошибки, схема подписи, пошаговое подключение и
отдельный раздел с допущениями. Подключить интеграцию можно, ни разу не
открыв спецификацию. Фикстуры — три вида, как просил кейс: запросы, ответы,
уведомления. Подпись в уведомлении настоящая — это реальный HMAC, его
проверяет наш тест».

## Экран 4. Чужая спека и отчёт

**Вставить в терминал:**

```sh
docker compose run --rm api ./integrate --spec spec/fixtures/specs/real/adyen_transfers_v4.yaml --provider adyen --output output/adyen
```

Хвост `--output output/adyen` обязателен: без него файлы Adyen лягут поверх
файлов novapay, и второй экран будет нечего показывать.

**Что появится.** Тот же процесс на чужой спецификации: 12 операций, четыре
файла.

**Что сказать.** «Adyen Transfers — спецификация, которую мы не писали.
Сумма у них не число, а объект из значения и валюты; инструмент это разобрал.
Всего таких чужих спецификаций у нас в прогоне шесть».

Дальше переключиться в редактор с `output/broken/report.md` и показать строку
в разделе 2:

```
Непокрыто 26: вне контракта 4, структурных исключений 12, требует ручной работы 10.
```

**Что сказать.** «Мы делим непокрытое на три корзины. Первая — чужие ресурсы
спецификации, до которых контракту нет дела. Вторая — то, чему в четырёх
методах места нет по построению. И третья — единственная, адресованная
человеку: она печатается первой и целиком, поимённо. Вот этот список берут в
работу».

## Экран 5. Строка в справочнике при них

**Попросить эксперта назвать любое слово,** которым провайдер может обозначить
неуспешную выплату.

Переключиться в редактор с `rules/statuses.yml`, найти строку `rejected:`
(около строки 271) и **дописать одну строку** сразу под ней. Отступ — четыре
пробела, потом дефис, пробел и слово маленькими буквами:

```yaml
  rejected:
    - notok
```

**Вставить в терминал:**

```sh
docker compose run --rm api ./integrate --spec spec/fixtures/specs/broken.yaml --provider broken --output output/broken
```

**Что появится.** Последняя строка: «Предупреждения: **62**» вместо прежних
64.

**Что сказать.** «Ни одной строки кода, ни пересборки образа. Новый
провайдер для нас — это строки в справочнике. И чтобы это не осталось
обещанием, у нас есть тест, который запрещает имени провайдера появляться в
ядре вообще».

**Если названное слово уже есть в справочнике** — это тоже результат:
«смотрите, оно уже распознаётся», и попросить другое.

## Что делать, если

| Что случилось | Что делать |
|---|---|
| Терминал ругается на `docker` | `docker compose up -d --build`, подождать минуту, повторить |
| Веб не открывается | Не чинить при них: все файлы уже лежат в `output/`, показывать редактор |
| Команда идёт долго | Не ждать: сказать «файлы с прошлого прогона уже здесь» и открыть `output/` |
| Дали свою спецификацию, она не грузится | Это не провал, а ответ: показать сообщение — там имя файла и точное место ошибки |
| Спросили то, чего вы не знаете | «Не знаю, у нас это записано открытым вопросом» и открыть `docs/QUESTIONS.md` |

## Три вопроса, которые точно зададут

**«Почему покрытие не сто процентов даже на вашей спеке?»**

> «На выданной спецификации покрытие 98 % в границах контракта. Непокрытых
> элементов восемнадцать: три — операция баланса, до которой контракту нет
> дела, четырнадцать — поля ответа, которые четыре метода контракта не
> читают по построению, и **один** — настоящая работа, он назван в отчёте
> поимённо. Сто процентов тут были бы не достижением, а признаком того, что
> метрика считает не то».

**«А на других провайдерах работает?»**

> «Десять спецификаций в прогоне, шесть из них чужие настоящие: Adyen,
> PayPal, Paystack, GOV.UK Pay, Moov. Ни одна не останавливает генерацию».

Если попросят показать — команда:

```sh
docker compose run --rm api ./integrate --all
```

**«Нейросети внутри есть?»**

> «Нет. Словари, таблицы, строковые метрики и обход графа спецификации».

## Те же пять экранов без Докера

Если Докер не поднялся или его решили не трогать. Ruby на машине уже стоит,
ставить ничего не нужно.

### Одно предупреждение, из-за которого показ ломается

В **PowerShell** (синее окно, приглашение `PS E:\hackgenesis>`) команда
`./integrate` **не работает** — падает с «Cannot run a document in the middle
of a pipeline». Писать надо `ruby integrate`. Проверено.

В **Git Bash** (чёрное окно, приглашение `alexey@… MINGW64`) работает
`./integrate`, но нужна строка с `export PATH` — иначе Ruby не найдётся.

Дальше даны оба варианта. Достаточно одного — того окна, которое открыто.

### Первая команда в новом окне терминала

Выполняется **один раз** за сеанс, дальше не повторять.

PowerShell:

```powershell
$env:PATH = "C:\Ruby34-x64\bin;$env:PATH"
```

Git Bash:

```sh
export PATH="/c/Ruby34-x64/bin:$PATH"
```

### Экран 1. Одна команда — четыре файла

PowerShell:

```powershell
ruby integrate --spec provider_api.yaml --provider novapay --lang ruby
```

Git Bash:

```sh
./integrate --spec provider_api.yaml --provider novapay --lang ruby
```

### Экран 4. Чужая спека

Хвост `--output output/adyen` обязателен: без него файлы Adyen лягут поверх
файлов novapay, и второй экран будет нечего показывать.

PowerShell:

```powershell
ruby integrate --spec spec/fixtures/specs/real/adyen_transfers_v4.yaml --provider adyen --output output/adyen
```

Git Bash:

```sh
./integrate --spec spec/fixtures/specs/real/adyen_transfers_v4.yaml --provider adyen --output output/adyen
```

### Экран 5. После правки строки в `rules/statuses.yml`

PowerShell:

```powershell
ruby integrate --spec spec/fixtures/specs/broken.yaml --provider broken --output output/broken
```

Git Bash:

```sh
./integrate --spec spec/fixtures/specs/broken.yaml --provider broken --output output/broken
```

### Если попросят пакетный прогон

PowerShell:

```powershell
ruby integrate --all
```

Git Bash:

```sh
./integrate --all
```

Идёт около полутора минут — вживую лучше не запускать, только если попросят
прямо.

### Веб-интерфейс без Докера

**Сначала остановить контейнер**, иначе порт 9292 занят и сервер не
поднимется:

```powershell
docker compose down
```

Потом, в **отдельном окне** терминала (это окно останется занятым, пока
работает сервер):

PowerShell:

```powershell
$env:PATH = "C:\Ruby34-x64\bin;$env:PATH"
ruby bin/serve --port 9292
```

Git Bash:

```sh
export PATH="/c/Ruby34-x64/bin:$PATH"
ruby bin/serve --port 9292
```

Открыть <http://localhost:9292>. Остановить — `Ctrl+C` в том же окне.

## Чего не делать

- Не читать код вслух построчно — называть, что он делает.
- Не оправдываться за проценты: сразу называть три корзины.
- Не начинать с пакетного прогона `--all` — это ответ на вопрос, а не
  вступление.
- Не держать слайды на экране дольше полуминуты суммарно.
